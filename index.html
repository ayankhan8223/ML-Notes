What is Machine Learning?

Machine Learning ko ek line me samjho: data ke examples dekar system se pattern learn karwana, taaki wo naye input par useful output de sake.

Lecture timestamps: 00:04:30 - 00:19:58

Formal definition

Machine Learning computer science ka woh field hai jahan statistical techniques ki help se computers data se learn karte hain, bina har situation ke liye explicitly program kiye.

Simple language: ML ka main kaam hai data me chhupe patterns ko pakadna aur un patterns se new cases ka prediction karna.
Yaad rakhne wali line

Programming me hum rules likhte hain. ML me hum examples dete hain, aur system rules/patterns learn karta hai.

Explicit programming ka matlab

Agar kisi specific scenario ko handle karne ke liye programmer har condition ka code khud likhta hai, to woh explicit programming hai.

  • Har known condition ke liye rule.
  • New condition aayi to code update karna padega.
  • Rules bahut zyada ho jayein to system maintain karna mushkil.

Traditional programming flow

+

OutputResult

Logic pehle se programmer ke dimaag me hoti hai. System usi logic ko execute karta hai.

Machine learning flow

+
AlgorithmPattern search
=
ModelLearned logic

Model ko new input do, wo learned relationship ke basis par output predict karega.

Lecture ka simple example: addition

ApproachKaise kaam karta haiLimitation / strength
Traditional programProgrammer ne explicitly do numbers add karne ka code likha.Code jis input shape ke liye likha hai, wahi handle karega.
Machine LearningNumbers aur unke sums ke examples do; model addition ka pattern learn karega.Learned pattern new examples par apply ho sakta hai.
Important nuance: Ye example intuition ke liye hai. Real ML model “addition ka universal rule” magically nahi samajhta; uski generalization training data, model aur problem setup par depend karti hai.

Machine Learning kab traditional programming se better hoti hai?

Scenario 01

Rules bahut zyada hain

Email spam filter me har spam word aur pattern ka if-else rule likhna fragile ho jayega. Spammer wording change karega to rules baar-baar update karne padenge.

Scenario 02

Cases enumerate nahi kar sakte

Dog image classification me breeds, size, color, angle aur lighting ke infinite combinations hain. Har case ka code likhna practical nahi.

Scenario 03

Hidden pattern chahiye

Graphs se jo pattern visible nahi ho raha, ML model us data me deeper relationship discover karne me help kar sakta hai. Isse data mining kehte hain.

Data analysis vs data mining

Data analysis: graphs, summaries aur visualizations se patterns samajhna.

Data mining: ML algorithms ko use karke data me deeper ya hidden patterns discover karna.

Example: shopping data me products ka relation dekhkar recommendation ya store layout improve karna.

ML boom kyon aaya?

  • Internet aur smartphones ki wajah se data generation bahut badhi.
  • Modern hardware, GPUs aur cloud compute affordable hue.
  • Algorithms, libraries aur deployment tools mature hue.
  • Data + compute + better algorithms ne ML ko practical banaya.

AI vs ML vs DL

AI broad goal hai. ML AI ko data se build karne ka approach hai. DL ML ka neural-network based subset hai jo features bhi automatically learn kar sakta hai.

Lecture timestamps: 00:00:00 - 00:16:28

AI ka matlab kya hai?

Artificial Intelligence ka broad aim hai machines ko aise tasks karwana jahan intelligence ki zarurat hoti hai.

  • Reasoning aur problem solving.
  • Planning aur decision making.
  • Language understanding.
  • Vision, perception, creativity ya learning.
AI is a goal/umbrella: AI ke andar rule-based systems, search, expert systems, ML aur DL sab aa sakte hain.

Rule-based system se ML tak

Expert / symbolic system

Expert se knowledge lekar knowledge base aur if-then rules banaye jaate hain. Closed, well-defined problems me useful, lekin rules bahut badhne par maintenance difficult.

->
PredictionNew case

Machine Learning

ML me input data ko algorithm ke through process karke model banaya jaata hai. Model new data par prediction karta hai.

  • Feature engineering aksar manually karni padti hai.
  • Data quality aur feature choice ka impact bahut high hota hai.
  • Tabular/business data par classical ML strong ho sakta hai.

Deep Learning

DL multi-layer neural networks ka use karta hai. Layers raw data se increasingly useful representations/features learn kar sakti hain.

  • Image, audio, text aur complex unstructured data me powerful.
  • Usually zyada data, compute aur training time chahiye.
  • Feature extraction ka kaam network ke andar learn ho sakta hai.

Feature engineering ka difference

Classical ML: Tumhe decide karna pad sakta hai ki dog image ke liye ears, eyes, shape, color jaise kaunse features useful honge.
Deep Learning: Network multiple layers ke through low-level patterns se high-level representation tak features learn kar sakta hai.
Raw image -> edges -> shapes -> parts -> object class

Ye hierarchy intuition ke liye hai. Actual neural network architecture, task aur training data par depend karegi.

One-year-later memory hook

Quick self-check

Kya AI aur ML same hain?

Nahi. AI broad umbrella/goal hai; ML AI banane ka data-driven subset hai.

Deep Learning ko “deep” kyon bolte hain?

Kyuki neural network me multiple processing layers hoti hain jo representations ko layer-by-layer learn karti hain.

Classical ML kab better choice ho sakta hai?

Structured data, smaller datasets, strong domain features, faster iteration aur interpretability wale cases me.

05

Online Machine Learning

Online learning me model ko data ke small chunks milte rehte hain aur wo gradually update hota rehta hai. Iska focus fast adaptation aur efficient training hai.

Lecture timestamps: 00:00:00 - 00:19:38

Online learning ki definition

Online learning, jise incremental learning bhi kehte hain, me model ko data ek stream ya small batches me diya jaata hai. Har update ke baad model next data ke liye thoda better adapt kar sakta hai.

Online learning kab useful hai?

  • Data continuously aa raha ho: clicks, transactions, sensor readings.
  • Problem ka nature time ke saath fast change hota ho.
  • Dataset itna bada ho ki memory me ek saath fit na ho.
  • Frequent retraining ka cost ya latency avoid karni ho.
  • Model ko recent behavior ke saath adapt karna ho.

Real-world examples

  • E-commerce recommendations: new movies/products aur changing user taste.
  • Email spam: attackers naye words aur patterns use karte rehte hain.
  • Fraud detection: transaction patterns time ke saath shift hote hain.
  • Large-scale logs: data stream ko chunks me process karna.

Learning rate aur old knowledge

Online learning me learning rate decide karta hai ki new data model ko kitna change karega.

Very high

Fast change

Model recent data ko bahut weight de sakta hai aur purane patterns quickly bhool sakta hai.

Very low

Slow adaptation

Model stable rahega, lekin real drift ke saath adapt karne me time lagega.

Balanced

Useful memory

New trends learn hon aur old useful knowledge bhi unnecessarily erase na ho.

One-year-later memory hook

Online learning ka real challenge sirf update karna nahi; sahi speed se update karna hai.

Tools aur implementation idea

Scikit-learn ke kuch estimators incremental training support karte hain, jaise SGDRegressor aur SGDClassifier, jahan partial_fit() se data chunks process kiye ja sakte hain.

River: Python ki online/streaming ML library hai, jo ek-ek observation ya small batch ke saath model update karne ke workflows ke liye useful hai.

Vowpal Wabbit: fast, large-scale online learning framework hai, jise continuously aane wale data par incremental training ke liye use kiya ja sakta hai.

Library se zyada important concept hai: data stream ko handle karna, model update karna, aur performance monitor karna.

Instance-Based vs Model-Based Learning

Ye classification model ka ek alag lens hai: kya model training examples ko yaad rakhta hai, ya un examples se ek generalized mathematical rule learn karta hai?

Lecture timestamps: 00:00:00 - 00:17:17

Do learning styles ka simple analogy

Ratta / memorization: Examples yaad rakho aur new question aane par similar example dhoondo.
Concept samajhna: Examples ke peeche ka principle samjho aur us principle se unseen question solve karo.

Machine Learning me bhi kuch algorithms data points ko store karke similarity se answer dete hain, jabki kuch algorithms data se decision rule ya mathematical function learn karte hain.

Instance-Based Learning

Training data points ko store kiya jaata hai. Prediction ke time new point ko stored examples ke saath compare karke answer diya jaata hai.

Store examplesTraining data retained
->
New queryUnseen point
->
SimilarityDistance / neighbors
->
PredictionNearby labels

Lecture ka example: K-Nearest Neighbors (KNN) me new student ke IQ/CGPA point ke nearest students dekho; majority placement label prediction ban sakta hai.

Model-Based Learning

Training data se underlying relationship learn karke ek compact model, function ya decision boundary banayi jaati hai.

Training dataExamples
->
Learn ruleMathematical pattern
->
New queryOnly model needed
->
PredictionGeneralized rule

Examples: Linear Regression, Logistic Regression aur kai algorithms jo input-output relationship ko function/boundary me represent karte hain.

Lecture ka same example: IQ + CGPA se placement

Yahan input features IQ aur CGPA hain, aur target Placement hai. Training data se ek naye student ka placement Yes/No predict karna hai.

IQCGPAPlacement
808.0Yes
707.0No
1037.5? New query
Mathematical function note: Ye dashed circle KNN ki local neighborhood hai, global mathematical function nahi. Mathematical function ya decision boundary model-based learning me learn hoti hai.

Instance-based: KNN

  1. New query point (103, 7.5) ko graph par place karo.
  2. Is point ka har training point se distance/similarity calculate karo.
  3. Nearest K students choose karo; maan lo K = 3.
  4. Agar 3 me se 2 students ka placement Yes hai, to majority vote se answer Yes hoga.
(103, 7.5) -> nearest students -> majority vote -> Placement = Yes
Key idea: KNN koi boundary pehle se learn nahi karta; query aane par nearby examples dekhkar answer deta hai.

Model-based: decision boundary

Isi IQ-CGPA data se algorithm ek mathematical relationship ya decision boundary learn karega, jo Yes aur No students ke regions ko separate karegi.

Training data -> learned boundary -> (103, 7.5) -> Placement = Yes / No

Prediction ke time original students ko ek-ek karke compare karna zaroori nahi; learned rule se new point classify ho sakta hai.

Core difference: Instance-based me “similar student dhoondo”; model-based me “general rule apply karo”.

Algorithm dekhkar type kaise identify karein?

  • Kya algorithm prediction ke time training examples ke neighbors/distance use karta hai? -> Instance-based.
  • Kya algorithm coefficients, parameters, function ya decision boundary learn karta hai? -> Model-based.
  • Question ka purpose algorithm yaad karna nahi, algorithm ka learning behavior samajhna hai.
One-year-later memory hook

Instance-based = “similar cases dhoondo.” Model-based = “general rule apply karo.”

Challenges in Machine Learning

Real ML project me algorithm choose karna ek part hai. Sabse difficult work aksar data, generalization, integration, deployment, monitoring aur cost se related hota hai.

Lecture timestamps: 00:00:00 - 00:24:06

1. Data Collection

Machine Learning data se learn karta hai. Agar relevant data available hi nahi hai, ya collected data insufficient hai, to useful model banana difficult ho jaata hai.

  • College projects me CSV, public datasets ya APIs se data mil sakta hai.
  • Real-world projects me data collect karna costly, slow aur domain knowledge dependent ho sakta hai.
  • Health department, business systems, APIs ya web scraping jaise sources use ho sakte hain, lekin privacy/legal rules ka dhyan zaroori hai.
  • Data quantity ke saath relevance, coverage aur quality bhi check karo.

2. Insufficient Data / Labelled Data

Data collect ho gaya to next questions aate hain: kya examples sufficient hain, aur kya data properly labeled hai?

  • Enough examples na hone par model unstable ya misleading patterns learn kar sakta hai.
  • Images, audio aur text ko label karne me human effort, domain knowledge aur money lagta hai.
  • Labeling guidelines clear rakho aur quality checks/multiple reviewers use karo.
  • Unlabeled data zyada ho to semi-supervised learning consider kar sakte ho.

3. Non Representative Data

Training data agar real-world population ko represent nahi karta, to model ka result unreliable ya biased ho sakta hai. Is challenge ko samajhne ke liye sampling noise aur sampling bias dono important hain.

Sampling Noise: Sample chhota hone par random variation aa sakti hai. Sample badhne par ye random error generally reduce hoti hai.
Sampling Bias: Sample systematically kisi ek group ki taraf tilted ho, to zyada data collect karne par bhi wrong pattern repeat ho sakta hai.
World Cup example

Sirf India me survey karoge, to India ke favour me result aayega: ye sampling bias hai. Randomly kuch log choose karne ki wajah se result thoda change ho: ye sampling noise ho sakti hai.

Check before training

Training distribution aur production distribution compare karo. Jo groups production me aayenge, unke examples training me bhi hone chahiye.

4. Poor Quality Data

Missing

Values absent

Imputation ya business rule se handle karna padega.

Inconsistent

Formats mismatch

Dates, categories, units aur spelling normalize karni padegi.

Noisy

Wrong records

Invalid values, duplicates, measurement errors aur outliers inspect karo.

ML project ka large portion data cleaning aur validation me ja sakta hai. Better algorithm garbage data ko automatically useful data me convert nahi karta.

5. Irrelevant features

Har column useful signal nahi hota. Irrelevant feature noise add kar sakta hai, model ko confuse kar sakta hai aur computation badha sakta hai. Lecture ke marathon example se dekho ki raw columns ko kaise useful signals me convert karte hain.

Raw columnsExample: age, weight, height, location, training days
->
Domain checkExample: location marathon participation ko really explain karta hai?
->
Feature selectionExample: weight, height aur training days rakho; irrelevant location hatao
->
Feature engineeringExample: weight + height se BMI jaisa meaningful feature banao
Marathon takeaway: Location ko sirf isliye feature mat rakho kyunki column available hai. Evidence ho tabhi use karo; warna model ko unnecessary noise milega.

6. Overfitting

Overfitting = ratta maarna: Model training data ke actual pattern ke saath-saath uska noise aur exceptions bhi memorize kar leta hai. Isliye training data par excellent score aata hai, lekin unseen data par prediction weak ho jaati hai.

Lecture analogy: Gurgaon me ek movie ticket Rs 500 ka mila aur humne conclude kar liya ki Gurgaon me har cheez expensive hai. Ek example ko general rule samajhna overfitting jaisa hai.

7. Underfitting

Underfitting = bahut simple rule banana: Model data ke important patterns ko properly learn hi nahi kar pata. Isliye training data aur new data, dono par performance weak hoti hai.

Same Gurgaon analogy: Agar hum rule bana dein ki “har movie ka ticket Rs 500 hota hai” aur theatre, movie, timing ya seat type ko ignore kar dein, to rule bahut simple hai. Ye actual pattern ko capture nahi karta, isi ko underfitting samjho.

8. Software Integration

ML model usually kisi user-facing software ka part hota hai: website, mobile app, banking system, recommendation engine ya industrial tool.

ModelNotebook artifact
->
API / servicePrediction endpoint
->
ProductWeb / app / device
->
UsersReal predictions

Different platforms, latency, model format, dependency compatibility, security aur reliability ki wajah se integration challenging hoti hai. Notebook me model banana final goal nahi; users ko usable product dena goal hai.

9. Offline Learning / Deployment

Offline learning me update ke liye model ko retrain karke server par redeploy karna pad sakta hai. Online learning me model continuously update hota hai, lekin monitoring aur control zyada difficult hota hai.

  • Online model ke liye continuous monitoring, data validation aur rollback strategy chahiye.
Deployment challenge: Model banana alag step hai; usko reliably serve, update aur monitor karna alag engineering problem hai.

10. Cost Involved

Large scale par ML model ko run karne ka hidden cost aa sakta hai: inference servers, storage, logs, monitoring, retraining aur compute.

  • High traffic par serving aur infrastructure cost badh sakti hai.
  • Model performance, data drift, latency aur business KPI monitor karna zaroori hai.
  • MLOps ka focus ML ko reliable software product ki tarah build, deploy aur maintain karna hai.
Production mindset: Accuracy ke saath cost, speed, reliability, fairness, security aur maintainability bhi success ka part hain.

Applications of Machine Learning

Machine Learning future ki sirf theory nahi hai. Retail, banking, transport, manufacturing aur social media products me already real business decisions drive kar raha hai.

Lecture timestamps: 00:00:00 - 00:29:30

Consumer products se B2B business tak

ML ke common consumer examples Facebook friend recommendation, YouTube video recommendation aur Amazon product recommendation hain. Lekin ML ka important impact B2B systems me bhi hota hai, jahan model directly business ki cost, stock, risk ya revenue decision improve karta hai.

B2C: User ko better experience dena: recommendation, search ranking, personalized content.
B2B: Business ko better decision dena: demand forecast, credit risk, targeted marketing, route optimization.

Common loading problems

CSV simple lagta hai, but real datasets me chhote issues aate rehte hain. Lecture ka intention ye tha ki read_csv ke parameters se tum un cases ko handle kar pao.

  • Wrong separator: columns ek hi column me aa rahe hain, use sep.
  • Bad header: column names wrong aa rahe hain, use header / names.
  • Unwanted columns: memory waste ho rahi hai, use usecols.
  • Date as string: date operations nahi chalenge, use parse_dates.
  • Custom blanks: ?, -, NA ko missing mark karne ke liye na_values.

Chunks for big data

Jab CSV RAM me fit nahi hoti, tab complete file ek saath load karne ke bajay chunks me read karo. Har chunk ek DataFrame hota hai jiske upar loop me operation apply kar sakte ho.

chunks = pd.read_csv("big.csv", chunksize=5000)
for chunk in chunks:
    process(chunk)
Yaad rakhna: chunksize memory problem ko manageable banata hai, especially jab file millions of rows wali ho.

Har binning method ko samjho

Equal-width / Uniform

  • Kaise: Minimum aur maximum ke beech ka range equal-size intervals me divide hota hai.
  • Formula: (max - min) / number_of_bins
  • Example: Age 0-100 ko 5 bins me baantoge to 0-20, 20-40, 40-60, 60-80, 80-100 bands banenge.
  • Point: Har interval ki width same hoti hai, observations ki count zaroori nahi.

Equal-frequency / Quantile

  • Kaise: Percentile boundaries choose hoti hain; 10 bins me har bin me lagbhag 10% data aata hai.
  • Benefit 1: Outliers par accha kaam: Extreme values poore range ko stretch nahi karte; outlier apne percentile group me absorb ho jata hai.
  • Benefit 2: Value spread uniform: Har bin me roughly equal observations aati hain, isliye data ka spread zyada balanced dikhta hai.
  • Trade-off: Bin widths equal nahi hoti. Natural business boundaries important hon to equal-width ya custom bins better ho sakte hain.

K-Means / Natural groups

  • Kaise: Similar values ke around centroids bante hain aur values nearest centroid ke group me assign hoti hain.
  • Example: Google Play downloads me low-download, medium-download aur very-popular apps ke natural clusters.
  • Kab: Jab data clearly separate clusters me spread ho.

Supervised Decision-Tree Binning

  • Target use: Bins banate waqt target label bhi dekha jata hai.
  • Kaise: Decision tree woh cut-points choose karta hai jo target classes ko best separate karein.
  • Dhyan: Train/test split aur data leakage ka care rakho.

Custom Binning

  • Kaise: Domain knowledge se boundaries manually decide hoti hain.
  • Example: Age ko child, adult, senior groups ya income ko tax slabs me baantna.
  • Kab: Jab business rules aur category meaning pehle se clear ho.

Mean/median imputation: kab use karein aur trade-offs

Kab use karein? Jab missingness MCAR ho, missing values randomly distributed hon, aur missing observations roughly 5% se kam hon. Is condition me simple mean/median baseline practical ho sakta hai.

Advantages

  • Simple: Samajhna aur production me implement karna easy.
  • Fast: Sirf ek statistic learn hota hai.
  • Outlier-aware choice: Skewed/outlier-heavy data me median, mean se safer hota hai.
  • Small missingness: MCAR aur roughly 5% se kam missing data me practical baseline.

Disadvantages

  • Outlier problem: Mean imputation me extreme outliers mean ko shift karke har filled value ko misleading bana sakte hain.
  • Distribution change: Mean/median par artificial peak ban sakti hai.
  • More missing values: Missing data zyada ho to wahi mean/median baar-baar repeat hota hai; artificial peak aur distribution distortion aur badh sakta hai.
  • Variance shrink: Repeated central value spread ko kam karti hai.
  • Relationships change: Doosre columns ke saath covariance/correlation distort ho sakta hai.

def random_sample_impute(train, test, column):
  train = train.copy()
  test = test.copy()
  train[column + '_random'] = train[column]
  test[column + '_random'] = test[column]

  train_missing = train[column].isna().sum()
  test_missing = test[column].isna().sum()
  observed = train[column].dropna()

  train.loc[train[column].isna(), column + '_random'] = observed.sample(train_missing, replace=True, random_state=42).to_numpy()
  test.loc[test[column].isna(), column + '_random'] = observed.sample(test_missing, replace=True, random_state=42).to_numpy()
  return train, test

MICE: Iterative Imputer

MICE (Multivariate Imputation by Chained Equations) har incomplete feature ko baaki features se predict karta hai aur estimates ko multiple iterations me refine karta hai.

Missingness patterns: MCAR, MAR aur MNAR

Lecture ke overview me missing data ke teen patterns bataye gaye. MICE har case me run ho sakta hai, lekin uska strongest use-case MAR hai kyunki woh baaki observed columns se missing value predict karta hai.

1
MCAR

Missing Completely At Random: Data collection/system issue ki wajah se value random missing hai; missingness kisi column ya person-group se related nahi.

MICE: Use ho sakta hai, lekin simple imputation bhi baseline ho sakti hai because predictable pattern zaroori nahi milta.

2
MAR: MICE ke liye best

Missing At Random: Missingness ko doosre observed columns explain kar sakte hain. Example: income missing hai, par age, education aur job se estimate possible hai.

Why MICE? Ye remaining columns ki relationship use karke missing column predict/refine karta hai.

3
MNAR

Missing Not At Random: Value khud missing hone ka reason hai, jaise koi apni income disclose nahi karna chahta. Observed columns se reason fully explain nahi hota.

Risk: MICE result biased ho sakta hai; blindly impute karna safe nahi.

Memory rule: MCAR = random loss; MAR = baaki columns se explainable, isliye MICE ka best case; MNAR = missing value khud reason se linked, isliye hardest case.

Outlier sirf ek extreme number nahi; woh error, rare valid case, important anomaly, ya missing context ka signal ho sakta hai.

Definition aur intuition

Outlier woh observation hai jo majority data points se unusually door behave kare. Salary data me ek billionaire mean ko distort kar sakta hai; study-hours vs marks data me do unusual students fitted regression line ko apni taraf kheench sakte hain.

PCA: Problem Formulation & Step-by-Step Solution

PCA ka mathematical objective: aisa unit direction find karo jiske upar projected data ka variance maximum ho, phir top directions par data project karke dimensions reduce karo.

Problem formulation: 2D data ko 1D me lana

Maan lo dataset me n observations aur p numerical features hain. Har observation xᵢ ∈ ℝᵖ ek vector hai. Hume ek direction u find karni hai aur saare points ko us direction par project karna hai.

SymbolMeaningShape
XInput-feature matrixn × p
xᵢEk observation/row vectorp × 1
uCandidate projection direction; unit vectorp × 1
zᵢxᵢ ka new 1D coordinatescalar
Constraint kyu? uᵀu = 1 rakhna zaroori hai. Agar direction ki length unrestricted ho, to u ko arbitrarily bada karke projected variance fake tareeke se infinite ki ja sakti hai.

Step 1 — ek point ko direction u par project karo

General vector projection me denominator uᵀu hota hai. PCA me u unit vector hai, isliye denominator 1 ho jata hai.

Scalar projection / new coordinate:
zᵢ = uᵀxᵢ

Projected vector on the line:
x̂ᵢ = (uᵀxᵢ)u

If u = [u₁, u₂]ᵀ and xᵢ = [xᵢ₁, xᵢ₂]ᵀ:
zᵢ = u₁xᵢ₁ + u₂xᵢ₂

PCA output me usually scalar coordinate zᵢ store hota hai. Har original point ko project karoge to z₁, z₂, …, zₙ ki one-dimensional list milti hai.

Step 2 — projected values ka variance maximize karo

Projected mean z̄ = uᵀx̄ hota hai. Isliye projection variance ko matrix form me simplify kar sakte hain:

Var(z) = (1/n) Σᵢ (zᵢ − z̄)²
= (1/n) Σᵢ [uᵀ(xᵢ − x̄)]²
= uᵀ [(1/n) Σᵢ (xᵢ − x̄)(xᵢ − x̄)ᵀ] u
= uᵀSu

Bracket ke andar wali matrix S covariance matrix hai. PCA ka formal optimization problem:

maximize  uᵀSu
subject to  uᵀu = 1
Lecture ki most important line: Hume woh unit vector u chahiye jiske upar saare points project karne ke baad variance maximum aaye.

Variance se covariance tak

Variance ek feature ka spread batata hai, lekin multiple features ki orientation/relationship nahi. Covariance batata hai ki do features saath me kaise change karte hain.

Var(X₁) = (1/n) Σᵢ (xᵢ₁ − x̄₁)²

Cov(X₁, X₂) = (1/n) Σᵢ (xᵢ₁ − x̄₁)(xᵢ₂ − x̄₂)
CovarianceInterpretation
PositiveX₁ badhta hai to X₂ bhi generally badhta hai.
NegativeX₁ badhta hai to X₂ generally ghatta hai.
Near zeroStrong linear co-movement nahi dikh raha.
Covariance vs correlation: Sign ka intuition similar hai, lekin correlation standardized hokar −1 se +1 ke beech hota hai; covariance ki fixed range nahi hoti.

Covariance matrix ka structure

p features ke liye covariance matrix ka shape p × p hota hai. Diagonal par individual variances aur off-diagonal par pairwise covariances aati hain.

For two features:

S = [ Var(X₁)      Cov(X₁,X₂) ]
    [ Cov(X₂,X₁)  Var(X₂)     ]

Matrix form for centered X:
S = (1/n)XᵀX   or sample convention   S = (1/(n−1))XᵀX
  • Cov(X₁,X₂) = Cov(X₂,X₁), so covariance matrix symmetric hoti hai.
  • Diagonal values data ka axis-wise spread batati hain.
  • Off-diagonal values data ki orientation/tilt batati hain.
  • Isi matrix me dataset ke spread aur linear orientation ki combined information hoti hai.

Matrix transformation, eigenvectors aur eigenvalues

Matrix ko ek linear transformation ki tarah samjho: woh coordinate space ko rotate, stretch, shrink, reflect ya squash kar sakti hai. Most vectors ka direction transformation ke baad change hota hai, lekin kuch special vectors apni line/direction preserve karte hain.

Av = λv
TermMeaning
ATransformation matrix
vEigenvector: transformation ke baad same line/direction me rehta hai
λEigenvalue: eigenvector kitna stretch/shrink/flip hua

λ > 1 stretch, 0 < λ < 1 shrink aur negative λ direction flip ke saath scaling represent kar sakta hai.

Optimization ka solution eigenvector kyu hai?

Lecture me optimization ka direct result use hua: covariance matrix ke eigenvectors hi candidate principal directions hain. Lagrange-multiplier bridge se result:

L(u, λ) = uᵀSu − λ(uᵀu − 1)

∂L/∂u = 0
2Su − 2λu = 0
Su = λu

Ye exactly eigenvector equation hai. Aur agar u unit eigenvector hai:

Variance along u = uᵀSu
= uᵀ(λu)
= λ(uᵀu)
= λ
Core result: Covariance matrix ka eigenvector direction batata hai; corresponding eigenvalue us direction ka variance batata hai. Sabse badi eigenvalue ka eigenvector = PC1, second largest = PC2, and so on.

Complete PCA algorithm — lecture order

1. Center / scaleOrigin par lao
->
2. CovarianceSpread + orientation
->
3. Eigen decompositionDirections + variance
->
4. Sort & selectTop k PCs
->
5. ProjectNew coordinates
  1. Mean-center: Xc = X − μ. Lecture code me StandardScaler use hua, so centering ke saath scaling bhi hui: Xs = (X−μ)/σ.
  2. Covariance matrix: S = np.cov(Xs, rowvar=False).
  3. Eigen pairs: Svⱼ = λⱼvⱼ.
  4. Descending sort: λ₁ ≥ λ₂ ≥ … ≥ λₚ.
  5. Top k eigenvectors: columns me combine karke projection matrix Wₖ banao.
  6. Transform: centered/scaled data ko Wₖ se multiply karo.
Center vs scale: PCA ko mean-centered data chahiye. Scaling especially tab important hai jab features ki units/ranges different hon; warna large-scale feature variance dominate kar sakta hai.

Projection matrix aur shapes: 3D → 2D / 1D

Maan lo X me 1000 rows aur 3 features hain.

ObjectShapeMeaning
Xs1000 × 3Centered/scaled 3D data

Z = XsW₂1000 × 2New 2D dataset

Z = XsW₁1000 × 1New 1D dataset
Column-vector convention:
Z = Xs · Wₖ

If PCs are stored as rows (k × p), as in the lecture notation:
Z = Xs · PCsᵀ

Target column y projection calculate karne me use nahi hota; transform ke baad same target values new PC1, PC2, … features ke saath copy hoti hain.

Small mathematical example

Suppose centered/scaled two-feature data ki covariance matrix:

S = [ 1.0  0.8 ]
    [ 0.8  1.0 ]

Eigen pair 1:
λ₁ = 1.8,  v₁ = (1/√2)[1, 1]ᵀ  → PC1

Eigen pair 2:
λ₂ = 0.2,  v₂ = (1/√2)[1, −1]ᵀ  → PC2

Total variance λ₁ + λ₂ = 2.0. PC1 alone 1.8 / 2.0 = 90% variance capture karta hai. Isliye 2D → 1D reduction me PC1 retain karna sensible ho sakta hai.

From-scratch NumPy implementation

import numpy as np
from sklearn.preprocessing import StandardScaler

# X shape: (n_samples, n_features)
Xs = StandardScaler().fit_transform(X)

# p × p covariance matrix
S = np.cov(Xs, rowvar=False)

# S symmetric hai, so eigh is suitable
eigenvalues, eigenvectors = np.linalg.eigh(S)

# largest eigenvalue first
order = np.argsort(eigenvalues)[::-1]
eigenvalues = eigenvalues[order]
eigenvectors = eigenvectors[:, order]

# top k principal directions
k = 2
W = eigenvectors[:, :k] # shape: p × k

# transformed coordinates
X_pca = Xs @ W # shape: n × k
Lecture summary in one equation: covariance → eigenvectors/eigenvalues → top directions → dot product projection.

class SimpleLinearRegression:
  def fit(self, X, y):
    x = X.ravel()
    self.m = np.sum((x - x.mean()) * (y - y.mean())) / np.sum((x - x.mean()) ** 2)
    self.b = y.mean() - self.m * x.mean()
    return self

  def predict(self, X):
    return self.m * X.ravel() + self.b

1. MAE — Mean Absolute Error

Regression line se har point ki vertical distance lo. Point line ke upar ho ya neeche, sign ignore karna hai; isliye absolute value use hoti hai.

Advantage 1 — same unit
Package target ho aur MAE aaye, to seedha bolo: average prediction error 1.5 LPA hai.
Advantage 2 — outlier impact relatively kam
Distance ko square nahi kiya, isliye ek bahut large error MSE ke comparison me MAE ko relatively kam distort karta hai.
Disadvantage: Absolute-value graph zero par sharp corner banata hai. Function har point par differentiable nahi hota, isliye gradient-descent jaisi optimization methods me MAE convenient loss nahi hota.

2. MSE — Mean Squared Error

MAE me distance ka modulus tha. MSE me har distance ko square karte hain, phir unka average lete hain.

Advantage — differentiable loss
Squaring se error function smooth/differentiable hota hai. Isliye derivatives nikal kar model ko optimize kar sakte hain.
Large error par effect
Error double ho to squared penalty four times hoti hai. Agar large mistakes especially serious hon, yeh useful hai.
Disadvantage 1 — unit square ho jati hai
Package target ho to MSE LPA² me aata hai; direct real-world interpretation difficult hoti hai.
Disadvantage 2 — outlier sensitive
Outlier ka error square hokar bahut bada ban sakta hai, isliye MSE uske influence me zyada aa jata hai.

3. RMSE — Root Mean Squared Error

RMSE, MSE ka square root hai. Pehle squared errors use hote hain; last me root lene se result original unit me aa jata hai.

Advantage
Package target ho, to RMSE LPA me read hoga—MSE ke compared communicate karna easy hai.
MSE wala behavior retain
Square pehle lag chuka tha, isliye large errors ko RMSE bhi MAE se zyada importance deta hai.
Disadvantage: Outlier ka squared contribution pehle se present hai, so RMSE bhi outliers se strongly affect ho sakta hai.

  def __init__(self):

    self.intercept_ = None

  def fit(self, X_train, y_train):
    X_train = np.insert(X_train, 0, 1, axis=1)

Bias–Variance Trade-off

Variance
Training data thoda badle to fitted model kitna change hota hai. High-degree/too-flexible model me variance high hota hai.

Elastic Net = Ridge ka L2 shrinkage + Lasso ka L1 sparsity, both in one loss function.

Elastic Net ki zaroorat kyun padi?

Elastic Net dono methods ki useful strengths leta hai, kyunki Ridge aur Lasso dono ki apni limitation hai.

Sirf Ridge ki problem
Ridge correlated features ko stable rakhta hai, but coefficients ko usually exactly zero nahi karta. So irrelevant features model me remain kar sakte hain—automatic feature selection nahi milta.
Sirf Lasso ki problem

def perceptron(X, y, epochs=1000, lr=0.1):
    X = np.insert(X, 0, 1, axis=1)
    weights = np.ones(X.shape[1])

    for _ in range(epochs):
        idx = np.random.randint(0, X.shape[0])
        y_hat = step(np.dot(X[idx], weights))
        weights = weights + lr * (y[idx] - y_hat) * X[idx]

    return weights[1:], weights[0]

ROC Curve ki zarurat kyu padi?

Threshold change karne se kya badalta hai?

Spam filter me positive = spam. Do errors possible hain: FN: actual spam inbox me aa gaya; FP: genuine/important email spam folder me chala gaya. Dono errors ki cost equal nahi hoti.

Threshold high: t = 0.75 / 0.95
Model sirf very-sure emails ko spam bolega. Isliye genuine emails comparatively safe rahenge, but kuch actual spam emails inbox me miss ho sakte hain.
Threshold low: t = 0.10 / 0.20

Lecture intuition: threshold hume ek particular error ko reduce karne ki flexibility deta hai. But correct threshold 0.35, 0.50, 0.75 ya 0.90 kya hai—ye manually guess karna hard hai. ROC isi educated choice me help karta hai. Next section me is effect ko TPR aur FPR terms se name denge.

ROC ke two axes: benefit vs cost

TPR — True Positive Rate / Recall

Actual positive cases me se kitne correctly catch hue. Spam system me: actual spam emails me se kitne spam mark hue. Benefit samjho—system apna purpose kitna fulfill kar raha hai. Higher is better.
FPR — False Positive Rate

Actual negative cases me se kitno ko wrongly positive bola. Spam system me: genuine emails me se kitne spam folder me gaye. Cost samjho—wrong alarm ka damage. Lower is better.
